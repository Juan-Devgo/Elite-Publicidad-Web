# AGENTS.md

Static marketing site for "Élite Publicidad". Astro 5 + React 19 islands + Tailwind 4, content sourced from a Strapi CMS at build/request time. Single package, pnpm.

## Commands (pnpm)

- `pnpm dev` / `pnpm start` — Astro dev server
- `pnpm build` — production build to `dist/` (runs `astro check` first via `@astrojs/check`)
- `pnpm preview` — serve `dist/`
- `pnpm astro -- check` — type-check only, no build
- `pnpm exec prettier` — format (Prettier + `prettier-plugin-astro`)

No test runner, no lint script. Build is the only verification gate that runs `astro check`.

## Required env

- `PUBLIC_CMS_URL` — Strapi base URL. `.env` has `http://localhost:1337` for local dev; `.env.production` points to the live CMS. Both files are gitignored. Without a reachable CMS, the site builds with empty content (calls swallow errors, return `null`).

## CMS data flow (the core pattern)

1. `lib/content-manager.ts` is the **only** CMS gateway. Each `get*` function builds a Strapi `populate` query with `qs` and calls `getContent()`, which fetches `CMS_BASE_URL + url` and returns `data.data`. `getContent` swallows errors and returns `null` — every caller must tolerate `null`/missing fields.
2. Always run CMS media through `getMedia(raw, size)` from `lib/utils.ts` before use. It resolves `formats[size]` (`large`/`small`/`thumbnail`), prefixes the URL with `CMS_BASE_URL`, and detects image-vs-video into the local `Media` type (`types/media.ts`). Never read Strapi media fields directly in markup.
3. `src/layouts/main.astro` fetches navbar, footer, contact bar, and WhatsApp data itself. Page-specific content is fetched in the page's frontmatter (e.g. `index.astro` calls `getHeaderInicio()`).

When adding a CMS-backed section: add a `get*` in `content-manager.ts` with its `populate` shape, fetch it in the relevant page/layout frontmatter, map media through `getMedia`, pass plain props down.

## Components

- `.astro` = server-rendered. `.tsx` = React island, needs a `client:*` directive (see `NavbarClient`, `WhatsAppButton`).
- Icons exist in both `.astro` and `.tsx` forms (e.g. `icons/WhatsApp.astro` vs `WhatsApp.tsx`). Use `.tsx` inside React islands, `.astro` inside Astro markup.
- CMS images are optimized through Astro's `getImage` (`astro:assets`) — see `Navbar.astro` and the WhatsApp avatar in `main.astro`.

## Routes

File-based in `src/pages/`: `index`, `nosotros`, `contactanos`, plus `servicios/{impresiones,visibilidad,insumos,estructuras}`. Sitemap auto-generated by `@astrojs/sitemap`.

## Conventions

- **Spanish** domain/content field names throughout (`paginas`, `subpaginas`, `redes`, `telefonos`, `conocenos`, `callToAction`) — mirrors the Strapi schema. Match this in any CMS-mapped code.
- No path aliases configured — use relative imports (`../../lib/...`, `../../types/...`).
- `astro.config.mjs` `image.remotePatterns` whitelists remote image hosts. New CMS image domains must be added there.

## Gotchas

- `getContent` returns `null` on any failure — components must use `?.` and `?? []`/`?? ""` defaulting. Don't add try/catch around `getContent` calls; the null-tolerance is the contract.
- `pnpm build` runs `astro check` first. A type error fails the build, not just a warning. `pnpm astro -- check` is the faster local equivalent.
- `.env` and `.env.production` are gitignored. Don't commit CMS URLs.
- The `dist/` directory is a build artifact (not gitignored but recreated on build).
